# img_reader 상세 정리

이 문서는 [`backlog.md`](./backlog.md) 기준으로, 가칭 `img_reader`의 제품 방향과 동작 규칙을 좀 더 구체적으로 정리한 문서다.

## 1. 제품 목표

- mac 전용 이미지 뷰어로 간다.
- 핵심 경험은 스크롤 뷰어다.
- 기본 화면은 단순하고 조용해야 한다.
- 불필요한 관리 기능은 줄이고, 이미지를 빨리 여는 데 집중한다.
- EPUB, 북마크, 노트, 라이브러리 DB는 제외한다.

## 2. 제품 범위

### 유지

- ZIP, CBZ, RAR, CBR 압축 이미지 열기
- 일반 이미지 파일을 시작점으로 열기
- 스크롤 뷰어
- 페이지 모드 전환
- 이전/다음 페이지
- 10장 전/후
- 이전/다음 파일
- 1장 보기, 2장 보기
- fit 모드 전환
- 확대/축소
- 최근 파일 목록
- 마지막 위치 저장
- file explorer
- 단축키
- Finder 드래그 앤 드롭
- 캐시

### 제외

- EPUB
- 북마크
- 노트
- 라이브러리 DB
- TOC 기반 복잡한 이어읽기
- 텍스트 기반 리더

## 3. 화면 구조

### 3.1 기본 화면

- 기본 진입은 이미지 뷰어 중심이다.
- 아무 파일도 없을 때는 file explorer가 보이는 상태로 시작한다.
- 기본 화면은 최대한 심플하게 유지한다.

### 3.2 file explorer

- file explorer는 왼쪽 사이드 패널이다.
- file explorer는 이미지 뷰어를 가리지 않는다.
- file explorer는 단축키나 아이콘으로 열고 닫을 수 있다.
- file explorer는 폭 조절이 가능하다.
- file explorer는 디렉토리와 지원 파일을 같이 보여준다.
- 디렉토리를 선택하면 내부 파일 목록이 보인다.
- 지원하는 파일을 선택하면 바로 이미지 뷰어로 연다.
- 일반 이미지 파일을 직접 열면 그 파일이 시작점이 되고, 다음/이전은 같은 디렉토리의 다른 이미지 파일로 이동한다.
- file explorer 하단에는 최근 읽은 파일을 둔다.

### 3.3 뷰어

- 뷰어는 스크롤 모드를 기본으로 둔다.
- 페이지 모드는 전환 버튼으로 들어간다.
- file explorer가 열려 있어도 뷰어는 남아 있어야 한다.

## 4. 열기 플로우

### 4.1 file explorer에서 열기

- 사용자는 디렉토리, 지원 파일, 또는 일반 이미지 파일을 선택한다.
- 지원 파일을 선택하면 바로 뷰어가 열린다.
- 최근 읽은 파일이면 이어읽기 팝업 규칙을 탄다.

### 4.2 최근 파일에서 열기

- 최근 파일을 선택하면 이어읽기 팝업을 띄운다.
- 팝업은 `처음부터 / 최근 위치부터` 정도로 단순하게 유지한다.
- 최근 파일이더라도 옵션 토글에 따라 팝업이 생략될 수 있다.

### 4.3 Finder 드래그 앤 드롭

- 드래그 앤 드롭은 Finder에서 앱으로 끌어오는 흐름을 기본으로 둔다.
- file explorer 내부 드래그는 기본 전제가 아니다.

## 5. 이어읽기 규칙

- 최근 파일 캐시는 JSON으로 둔다.
- cache 파일에는 파일 위치, 파일명, 페이지 번호 또는 압축파일 내부 파일명을 남긴다.
- 파일 식별 기준은 `파일 위치 + 파일명` 조합이다.
- 이어읽기 팝업은 cache 파일이 있을 때만 띄운다.
- file explorer에서 선택한 파일도 같은 cache 파일 규칙을 따른다.
- 이어읽기 기능은 옵션에서 토글할 수 있다.
- 옵션을 끄면 팝업 없이 무조건 첫 이미지부터 연다.
- 토글 상태와 관계없이 cache 파일에는 위치 정보가 저장된다.

## 6. 캐시 정책

- 캐시는 흔한 이미지 뷰어 방식으로 시작한다.
- 성능을 보면서 프리페치 범위와 캐시 크기를 고도화한다.
- 작은 압축파일은 열자마자 통째로 캐시한다.
- 큰 압축파일은 부분 캐시 + 프리페치로 간다.
- 캐시 용량 한도는 설정에서 조절 가능하게 둔다.
- 캐시 한도는 메모리/디스크 각각 따로 다룰지 검토한다.

## 7. 스크롤 뷰어 규칙

- 스크롤 뷰어는 킬러 기능이다.
- 페이지 모드와 스크롤 모드는 전환 버튼으로 오간다.
- 스크롤 모드에서의 현재 위치는 복잡한 오프셋보다 현재 페이지 번호 중심으로 저장한다.
- 순차 읽기에서는 지연이 거의 느껴지지 않도록 만든다.
- 수십 장 점프에서는 짧은 준비 시간은 허용한다.

## 8. 파일 탐색기 키보드 규칙

- file explorer가 활성일 때는 탐색기 동작이 reader보다 우선한다.
- 위/아래 방향키로 항목 이동을 한다.
- `Enter`로 선택 항목을 연다.
- `Backspace`로 상위 폴더로 간다.
- file explorer가 열려 있을 때는 reader용 단축키보다 탐색 입력을 우선한다.

## 9. 단축키

### 9.1 file explorer

- 방향키로 탐색한다.
- `Enter`로 연다.
- `Backspace`로 상위 폴더로 간다.
- 자연스러운 탐색기 경험을 우선한다.

### 9.2 reader

- 이전 페이지
- 다음 페이지
- 10장 전
- 10장 후
- 이전 파일
- 다음 파일
- view 모드 전환: 스크롤 / 페이지
- 1장 보기
- 2장 보기
- fit 모드 전환: 폭 / 높이 / 균형

### 9.3 공용

- 설정창 열기
- file explorer 호출
- 새 창 띄우기

### 9.4 우선순위

- 공용 단축키를 제외한 나머지는 focus된 기능 기준으로만 동작한다.
- reader와 file explorer가 동시에 관련될 수 있는 입력은 현재 focus가 잡힌 쪽을 우선한다.

## 10. 세션 상태

- 마지막으로 열었던 파일 자동 오픈은 옵션으로 둔다.
- 이미지가 열려 있지 않은 상태에서는 사이드바가 열린 상태로 시작한다.
- 프로그램을 다시 열었을 때 복원할 항목은 단순하게 유지한다.
- 복원 대상은 최근 파일, 마지막 위치, 사이드바 상태 정도로 본다.

## 11. UI / UX 원칙

- 기본 화면은 빈 화면에 가깝게 유지한다.
- file explorer는 뷰어를 가리지 않는 왼쪽 패널이어야 한다.
- file explorer는 필요할 때만 튀어나오는 느낌으로 쓰되, 실제 구조는 사이드 패널이다.
- 최근 파일은 탐색 목록과 시각적으로 분리한다.
- 페이지 이동 시 현재 위치는 짧은 오버레이나 토스트로만 알려준다.
- 단축키 힌트는 첫 실행이나 첫 오픈 때만 가볍게 보여준다.
- 드래그 앤 드롭 안내와 에러는 화면을 과하게 가리지 않게 둔다.
- file explorer 폭과 같은 자주 쓰는 UI 상태는 기억한다.

## 12. 구현 원칙

- mac 전용으로 단순하게 간다.
- UI는 Swift shell, core는 Rust로 분리하되 먼저 단순한 구조로 만든다.
- 전체 압축 해제보다 필요할 때만 읽는 부분 추출과 캐시를 우선 검토한다.
- 최근 파일 목록과 마지막 위치만 남기고, 무거운 DB는 두지 않는다.
- 전달 데이터는 경로/핸들/메타데이터 중심으로 가볍게 유지한다.

## 13. 남겨둘 설정

- 이어읽기 팝업 on/off
- 캐시 용량 한도
- file explorer 폭
- 마지막 파일 자동 오픈
- 페이지 모드 / 스크롤 모드 전환

## 14. 진행 기준

- 순차 읽기가 부드럽게 느껴지는지 본다.
- 수십 장 점프 시 체감 지연이 거슬리지 않는지 본다.
- file explorer와 reader 전환이 막히지 않는지 본다.
- 최근 파일 복원과 이어읽기 팝업이 자연스러운지 본다.
- 기본 화면이 복잡하지 않은지 본다.
